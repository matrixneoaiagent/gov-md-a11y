# gov-md-a11y

Открытый индекс доступности государственных сайтов Молдовы (зона `.gov.md`).

Раз в месяц GitHub Actions обходят главные страницы всех хостов, которые когда-либо
встречались в Certificate Transparency для `*.gov.md`, и проверяют их по WCAG 2.2 A/AA,
заголовкам безопасности и мобильной вёрстке. Результат — статический отчёт на GitHub Pages
и машиночитаемый датасет.

## Что измеряется

| Блок | Чем | Вес в итоговой оценке |
|---|---|---|
| Доступность | axe-core (WCAG 2.0/2.1/2.2, уровни A и AA) | 50 % |
| Безопасность | HTTPS, валидность TLS, HSTS, CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` | 25 % |
| Мобильность | горизонтальная прокрутка при ширине 390 px | 15 % |
| Производительность | DOM-узлы, вес страницы, число запросов | 10 % |

Формула доступности: `100 × e^(−P/100)`, где `P` — сумма штрафов: 12/6/3/1 балла за
критичное, серьёзное, умеренное и мелкое нарушение, умноженные на `1 + log₂(число
затронутых элементов)`; одно правило даёт не больше 50 баллов штрафа.

Домены, отдающие служебную страницу хостера (Plesk, «Domain Default page»), помечаются
заглушками и не ранжируются — иначе пустая страница получает 100 баллов доступности.

## Как устроено

```
scripts/discover.mjs   crt.sh %.gov.md → нормализация → DNS → sites.json
scripts/audit.mjs      шард сайтов → TLS + fetch + Chrome/axe → results/<host>.json
scripts/merge.mjs      results/*.json → docs/ (HTML, отчёт, датасет)
.github/workflows/     discover (еженедельно), audit (ежемесячно, 20 шардов)
```

20 параллельных job'ов на `ubuntu-latest`, по ~20 сайтов на шард. Публичный репозиторий →
минуты Actions не расходуются из квоты. Полный прогон укладывается в 15–20 минут.

## Локальный запуск

```bash
npm ci
node scripts/discover.mjs          # обновить sites.json
node scripts/audit.mjs --limit 5   # проверить 5 сайтов
node scripts/merge.mjs             # собрать docs/
python3 -m http.server 8080 --directory docs
```

Нужен установленный Chrome (`PW_CHANNEL=chrome`) или `npx playwright install chromium`.

## Датасет

- `docs/data/sites.json` — компактные результаты по всем сайтам;
- `docs/data/site/<host>.json` — полный результат: нарушения с селекторами, заголовки, тайминги;
- `docs/data/summary.json` — агрегаты.

Схема записи:

```json
{
  "host": "example.gov.md",
  "url": "https://example.gov.md/",
  "status": 200,
  "scores": { "overall": 78, "a11y": 71, "security": 85, "mobile": 100, "performance": 92 },
  "flags": ["no-lang", "mobile-overflow"],
  "violations": [{ "id": "image-alt", "impact": "critical", "nodes": 12 }],
  "tls": { "ok": true, "validTo": "..." },
  "meta": { "lang": "ro", "title": "…", "transferBytes": 812345 }
}
```

## Ограничения

- Проверяется только главная страница; внутренние разделы не обходятся.
- axe-core автоматически находит лишь часть проблем WCAG — ручная проверка клавиатурой
  и скринридером по-прежнему нужна.
- Часть государственных сайтов блокирует запросы из дата-центров; такие хосты попадают
  в «не ответили» и не получают оценку.
- Оценка — срез одной страницы на дату аудита, а не рейтинг учреждения.
